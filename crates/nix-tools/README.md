# nix-tools

`nix-tools` provides the repository-neutral command boundary around Nix flakes.
Repository CLIs own their command names, argument parsing, output, selection policy, and extra
subcommands; they inject a `FlakeEngine`, `ProcessRunner`, `NixSystem`, and `AppOutputPolicy` into
`StandardCommands`.

`StandardCommands` routes builds, checks, and app realization through the same engine. It executes
an app only after the engine returns a `PreparedApp`, preserving exact trailing `OsString`
arguments and the supplied bounded output policy. `NixTools` is the small direct discovery service
for callers that need bounded `nix eval --json --apply builtins.attrNames` over standard flake
namespaces. `Flake::with_working_directory` lets both services resolve `.` or another relative
reference from a nested flake directory without changing the caller process directory.

The framework example exposes Rust packages beside a repository-owned shell package, check, and
app. This mixed output set is discovered through the same standard namespaces; repository-specific
commands remain ordinary branches in the repository CLI beside calls to `StandardCommands`.

`plan_json` accepts provider-neutral graph, scheduling configuration, and optional timing-history
JSON, then returns deterministic newline-terminated JSON generated by `nix-tools-core`.
